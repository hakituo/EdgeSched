## 11. 实验阶段划分

### 11.1 探索与校准

探索阶段用于：

- 找到可行驻留档位；
- 确定核心扩展曲线；
- 估计迁移、加载和 KV 代价；
- 校准安全余量、EMA、迟滞和候选配置；
- 排除没有收益的配置。

探索数据可以作为画像图或特性分析，但不能同时用于挑参数和证明主策略优于所有基线。

### 11.2 冻结

正式评测前必须冻结：

- 代码版本和提交哈希；
- 模型文件和哈希；
- 驻留档位；
- 核心候选；
- 安全余量；
- EMA、迟滞和决策规则；
- prompts、TTS 文本、声音配置和随机种子；
- 实验脚本和统计口径。

### 11.3 正式实验

正式实验使用新运行数据和预先冻结的配置。流程为：

\[
Implementation \rightarrow Calibration \rightarrow Freeze
\rightarrow Formal\ Evaluation \rightarrow Paper\ Update.
\]

## 12. 正式实验矩阵

### E0：正确性与真实后端确认

目的：证明实验没有静默回退到 Mock。

检查：

- 真实 Qwen3.5 GGUF 加载；
- 真实 Qwen3-TTS Base 输出；
- 真实 Forge 生成；
- KV 保存恢复；
- 设备与资源采样；
- SM 分区后端、请求比例和实际有效 SM 数验证；
- 取消、队列和失败闭合。

### E1：单模型画像

#### E1-L：LLM

- 驻留档位；
- CPU 核心数；
- 不同 KV / context 长度；
- TTFT、prefill、decode、token gap；
- 显存、内存和转换代价。

#### E1-T：TTS

- 完整 CPU、完整 GPU，以及后端支持时的组件级驻留配置；
- 每个组件配置的明确 device map 与主机/GPU 内存占用；
- 不同物理核心预算；
- 短、中、长句子 chunk；
- TTFA、RTF、资源峰值。

#### E1-D：Diffusion

- 标准 b=1 请求；
- 同 prompt 的 b=2、b=4；
- 不同分辨率与 steps；
- 冷加载和稳态执行；
- 显存时间线。

#### E1-G：GPU 计算份额

- MPS/Green Context 能力 preflight；
- TTS T0/T3 在离散有效 SM 档位下的 TTFA、RTF、显存和输出正确性；
- Diffusion b=1 在离散有效 SM 档位下的延迟、显存和利用率；
- LLM 仅对进入 S0 共享候选的驻留档位补测 SM 曲线；
- 请求百分比、实际有效 SM 数、后端、客户端 CUDA context 创建顺序和异常清理；
- 不受控共享作为必需基线。

### E2：无图像的 LLM→TTS 流水线

通用设计比较 S0-A、S0-B、S0-C(k)，S0-D 仅在可行时加入。当前 small C512 的执行集合以已冻结的具体配置为准：`K24:T0`、`K24:T3`、`K0:T0`、`K24:T4`；不按通用标签补入未验证的 FULL 组合。`K0:T4` 全 CPU 已以负面边界收案，不再进入主矩阵。

同时在 GPU 执行的配置先采用不受控共享；必要时补显存共驻留但计算串行的诊断对照，两者分别标记。静态 SM 分配仅在 E1-G 能力和性能验证通过后加入；当前 SM-B/C/D/E 为 PAUSED，不阻塞 E2。

场景：

- 单轮短回复；
- 单轮长回复；
- 连续多轮语音会话。

指标：

- 第一段文本时间；
- 首句完整波形就绪延迟与首次实际播放延迟（分别记录，不混称 TTFA）；
- 音频 gap / underrun；
- 完整语音回复时间；
- LLM tokens/s；
- 请求/实际有效 SM 数与 SM 配置切换成本；
- 转换成本及其跨轮摊销。

#### 当前 S0 端到端协议（`s0_protocol_v2`，2026-09-17 起）

**v2 相对 v1 的改动（2026-09-17）**：TTS 接入后端由上游动态路径换成加速 CUDA Graph
路径（与 B2 画像同口径：eager attention、x-vector 克隆、`do_sample=False`、非流式完整
波形）。该后端只暴露整模型 `device`，没有 talker/codec/speaker 分部件放置接口，因此
**TTS 放置维度只剩 `T0`**，正式配置由 4 档（`K24:T0`、`K24:T3`、`K0:T0`、`K24:T4`）降为
2 档（`K24:T0`、`K0:T0`）；`K24:T3`/`K24:T4` 显式排除，不沿用旧后端数值凑齐档位。

`s0_pipeline/config.py`，正式比较按配置对（placement × 启动策略）轮转编排，可离线复算。

#### 测量范围分层（2026-09-17，对 Gate B 的调整建议，需先确认）

播放链路的测量能力长期不达标（设备时钟映射始终未通过验证），因此把一次运行的证据
拆成两层，禁止互相冒充；对应已冻结的 `s0_protocol_v2`：

- **调度主指标**（`scheduling`，当前即可信，构成 Gate B 的形式判据）：
  首句/末句完整波形就绪、句级排队与合成时间、应用层供给缺口、资源门禁与输出契约。
- **设备体验指标**（`device_experience`，需要已验证的设备时钟）：可信的实际首播时间、
  设备 underflow。时钟未通过时一律 `pending_device_validation`，只保留 callback 代理
  观测并注明代理语义，**不拿代理冒充实际播放时刻**。

据此，Gate B 中「实际播放截止与播放连续性约束」不再作为当前 Go 的失败项：设备层
pending 表示测量能力不足，既不作为 Go 的充分条件，也不作为 No-Go 的失败项；调度层的
正确性、资源、首句/末句就绪、句级排队与合成、应用层供给缺口仍然照常判据（见第 10
模块 Gate B）。这是口径调整，必须先确认后再据此登记 Go/No-Go。

**公平性与容量边界。** 四配置使用相同输入与生成设置，保存实际生成文本、token 数、分句文本和音频时长；同一 seed 不替代输出一致性检查。输出差异超出预先约定范围时，按冻结规则处理并报告，不能静默删除慢或失败运行。固定文本重放可作隔离诊断，但不能冒充真实 LLM→TTS 端到端结果。

正式长回复或连续会话前，核对冻结 C512 口径对应的输入 tokens、输出/KV 余量和 `n_ctx`。多轮 reset/裁剪策略须统一记录；若无法在已验证边界内形成场景，先缩短场景或另立容量分支，不沿用 C512 阈值外推。

**冷热与统计。** 先独立预热并比较已驻留稳态；需要加载的冷路径单独从请求到达计时，包括真实加载/等待，不能与 warm 合并。运行期间继续保留资源与 swap 门禁，但不重估已冻结阈值。至少五次独立运行不等于足够的请求级 p95 样本；按第 08 模块分别核对请求与 chunk 样本数，保留运行级分组，不把同次运行的 chunk 当独立重复。

**证据产物。** 保存统一单调时钟下的 request、token/句提交、TTS 入队/开始/波形 ready、播放器提交/消费/结束事件及 underrun 记录；保存音频格式、设备缓冲配置和时钟映射。软件提交时间、播放模拟与设备实际消费必须区分。指标定义见第 08 模块；下述 pilot 仅报告生成与合成链路采集通过，不代表播放采集或完整端到端验收已通过。

#### S0 播放测量收尾：统计口径、时钟映射验证与一次启用播放的 K24:T0（2026-09-12，本地日期 UTC+8）

**播放器 smoke（非真实流水线实验）。** 输入为确定性合成音频（`playback_smoke.py`，
`--wav-dir` 可改用已保存 WAV；本批产物未落盘 WAV，输出为 BYTES）。判定拆两层：
`measurement_ok` 只判「能否可信地测量」，`continuity_ok` 单独报告且**不参与通过**。

**先修正统计口径（本轮的主要工作）。** 三处口径错误会让数字含义失真，已全部修正：

1. **单位**：缺数据的 callback 次数（`starve_callback_count`）不等于独立断流次数
   （`starve_episode_count`）。相邻缺音必须合并；只在缺音时上报的写法会让整轮被并成
   一段，因此改为每次 callback 都上报，`missing=0` 用于闭合当前段落。
2. **阶段**：每段按 `startup`（首句开播前的等待）、`inter_sentence`（等在下一句）、
   `intra_sentence`（句内缺音）、`tail`（末句结束后的补零）、`unknown` 分类。
   窗口取「首句开播设备位置 → 末句结束设备位置」，启动与收尾**不计入窗口内缺音**；
   归属不可确定时保留 `None`，不强行绑定。
3. **下标**：生产者样本下标（只随真实样本前进）与设备消费下标（补零也前进）必须分开。
   开播判据是「已交付真实样本数越过句子起点」，句子设备起点按所在块换算；断流起点
   要排除块内真实样本。修正前这两处都会让首播事件与归属偏掉一整段。

**时钟映射：判据不是偏移量大小。** PortAudio 只保证流时间单调递增，**起点未指定**，
因此与 host monotonic 相差很大本身不构成失效证据。判据改为四项：单位一致（设备跨度
/ host 跨度）、配对残差、漂移（仅在观测跨度 ≥1 s 时才判定，否则缓冲区量化会产生无意义
斜率）、单调性；`device` 时间取 callback 的 `outputBufferDacTime`（缓冲首样本 DAC 输出
时刻），不是 `currentTime`。四项任一不过即保留 `proxy`，并把残差/漂移/跨度比/采样耗时
全部落盘。

|---|---|---|---|---|---|
| Windows 真实设备 | 测得 0.987 s | 1 | 0.1979 | 未通过 | 残差 12.2–14.4 ms > 5 ms 容差 |
| WSL2（ALSA/pulse） | 测得 0.987 s | 1 | 0.1979 | 未通过 | 设备时间非单调、跨度比 1.12–1.16、残差 77–106 ms、漂移 73–117 ms/s |

采集侧的采样耗时（callback 间隔）也在产物中，可用来判断回调是否被拖慢。

| `K0:T0` | 5/5 | 18.66 | 74.7 | 2.04 | 1.25 | 7.0 | 0.543 | 65 | 8 |
| `K24:T4` | 4/5 | 36.66 | 263.8 | 8.04 | 87.10 | 8.0 | 0.861 | 80 | 9 |

**配对差（相对同 LLM 参考 `K24:T0`，按 `run_index` 配对，n=5；正值为目标更大）**

| 目标 | Δ首句就绪(s) | ΔRTF 均值 | Δ缺口段数 | 文本一致 | 通过轮次 |
|---|---:|---:|---:|---|---|
| `K24:T3` | +2.15 | +0.52 | 0.0 | 是 | 5/5 |
| `K0:T0` | +6.39 | +0.16 | −1.0 | 否（65 vs 80 token，8 vs 9 句） | 5/5 |
| `K24:T4` | +24.39 | +6.17 | 0.0 | 是 | 4/5（r2 swap 增长 63.1 MiB 失败） |

**三个冻结问题的回答。**

1. **`K24:T3`/`K24:T4` 是否改善了所报主指标？没有。** 两者在首句波形就绪与 RTF 上全部劣于
   `K24:T0`（`+2.15/+0.52`、`+24.39/+6.17`）。**但这里必须分清参考与基线**：`K24:T0` 本身就是
   混合驻留（32 层里上卡 24 层），所以本表的正确写法是「在这组旧后端实验中，`T3`/`T4` 相对
   `K24:T0` 未改善所报主指标」，**不能写成「混合驻留已被否定」**。相对 `K0:T0`（LLM 全 CPU），
   `K24:T0` 首句就绪快 6.39 s，但两者文本不同（65 vs 80 token、8 vs 9 句），
   **该收益判定受输出差异影响，尚未完成公平归因**，只能作为带混入标记的观察。
   本批四档**都是部分驻留**，因此也不能用来反证「完整共驻留（K32）可行」或「显存约束不存在」。
2. **改善是否只是文本更短、分句不同或预缓冲更多？唯一表层改善已被解释掉。** `K0:T0` 的
   缺口段数少 1 段（7 vs 8），但其 `confound_flags` 同时命中 `output_text_differs`、
   `sentence_count_differs`（8 vs 9 句）、`output_tokens_differ`（65 vs 80）；
   且其**窗口内缺口占比反而更差**（0.543 vs 0.423）。两档都是「每个句间边界都断一次」，
   段数差异只是边界数差异，不构成收益。本批四次运行的启动策略与预缓冲量完全一致
   （`first_sentence`、预缓冲 0），不存在预缓冲混入。
3. **哪些配置值得进入后续动态切换研究？在当前输入与旧后端下没有。** 候选只能靠第 2 条中
   已被解释掉的假改善支撑，因此**暂停**了以收益为前提的 planner 实现；这是「收益未确证」，
   不是「混合驻留已被否定」。按 [Gate B](../thesis_experiment_guide/10_gates_and_current_status.md)
   的 No-Go 第 1 条，本轮结论是**收缩主张**：不进入 `PlacementPlan`/predictor/planner 实现，
   改为报告静态放置结论与后端实时性边界；加速后端接入并重跑后再重新判读。

**边界与尚存的不确定性。**

- `K24:T4`（TTS 全 CPU）r2 唯一失败门为 swap 增长 63.1 MiB（容差 4 MiB），r3–r5 通过；
  失败计入分母，其 4 个通过轮次的指标仍整体最差（RTF 8.04、末句 263.8 s），支持
  「全 CPU TTS 放置不可用」的既有负面边界。
- 输出差异是**协变量而非删除理由**：`K24:T0/T3/T4` 三轮文本 SHA 一致（`45d7007f…`），
  `K0:T0` 不同（LLM 层在 CPU/GPU 的数值路径不同），已按要求标记并保留全部运行。
- 设备体验指标（可信实际首播、设备 underflow）全部为 `pending_device_validation`，
  本表**不含**任何实际播放时刻；末句就绪、缺口口径都只来自 host monotonic 与回调代理。
- 单轮 128 token、C512、单轮请求；本批未覆盖长回复、连续会话、图像或视觉阶段，
  因此不能外推为「所有 S0 场景都无收益」。
- **本轮结论绑定当前 TTS 后端**：四档都伴随 TTS 逐句 RTF > 1。同环境 A/B
  `tts_backend_both_eager_20260917_072516` 显示，同一 0.6B 模型换执行路径
  （静态 KV cache + CUDA Graph）后逐句 RTF 为 0.30–0.32（相对原后端 5.6–5.8×），
  见 [TTS 子系统](../../docs/TTS_SUBSYSTEM.md)。该后端**尚未接入** `s0_pipeline`
  （须升协议 v2 并重跑），因此本表「相对 `K24:T0` 未观察到改善」只在旧后端下成立；
  **换后端后关键路径落在哪一段仍是待验证预测**，必须用真实共跑事件验证，
  不能把隔离 RTF 与旧批次时序拼接后直接下结论。

### E3：Diffusion 期间的语音流水线

比较 S1-A、S1-B(k)、S1-C，S1-D(k) 仅在可行时加入。S1-C/S1-D 必须分别测试显存共驻留但计算串行、不受控并发和受控 SM 分配，不能把三种模式混成一个“共享 GPU”配置。

至少包含：

1. 普通单图请求；
2. 明确标记为压力测试的持续 GPU 占用场景。

指标：

- 图片资源准备和第一张图片时间；
- Diffusion slowdown；
- LLM TTFT、tokens/s 和 token gap；
- TTS TTFA、RTF 和音频断流；
- TTS/Diffusion 的请求与实际有效 SM 数；
- 不受控共享相对受控 SM 分配的尾延迟差异；
- 峰值显存、内存和 CPU 利用率。

### E4：CPU 核心与 GPU SM 分配

候选必须由 E1 推导，不能预先穷举等分组合。

步骤：

1. 求 \(c_T^{min}\)；
2. 测试其邻域；
3. 将剩余核心分配给 LLM；
4. 对最优两个候选做绑核、CCD、SMT 和系统保留核心消融。

随后对需要 GPU 共享的流水线：

1. 求满足 TTS 门槛的最小 \(s_T^{min}\)；
2. 将剩余 SM 分配给 LLM 或 Diffusion；
3. 只在临界点邻域补测，不穷举所有 CPU 核 × SM × 驻留档位组合；
4. 比较 CPU 分核、GPU 分 SM 以及二者联合启用，隔离每个维度的贡献。

### E5：代价感知策略对比

主基线：

| 策略 | 含义 |
|---|---|
| Serial/Wait | 保持当前驻留，竞争任务等待 |
| Always Full Migration | 当前完整 LLM 迁出/恢复策略 |
| Static Best | 使用校准阶段得到的固定最优配置 |
| Uncontrolled GPU Co-run | 显存允许时直接并发，不限制 SM |
| Static SM Split | 使用离线标定得到的固定 SM 份额 |
| Pareto-Only Instantaneous | 枚举当前 SLO-feasible 配置，Pareto 过滤后按固定字典序选择；不看转换成本或队列视界 |
| Transition-Cost-Aware | 只对当前 phase 比较收益与转换成本，不累计已经到达的后继工作 |
| Queue-Horizon-Aware EdgeSched | 在已经到达的 phase/queue 视界内累计收益，联合选择驻留、CPU 核、SM、batch 和转换方式，并受最小驻留窗口约束 |
| Oracle | 使用真实未来执行时长进行事后最优选择 |

迁移机制基线可保留：

- Cold Restart；
- Symmetric Migration；
- Urgent Down + Atomic Hot-Swap Up。

这些基线回答的是状态转换机制问题，不能替代新版在线规划策略基线。正式比较必须分别报告
SLO、端到端完成时间、吞吐、转换次数、真正完成 payback 的转换比例，以及相对 oracle 的
decision regret。Pareto-only 是可解释的决策基线，不单独作为 EdgeSched 的算法贡献。

### E8：消融与稳健性

消融：

- 无时长预测；
- 无在线 EWMA 残差修正，只使用离线画像插值；
- 无 queue horizon，只看当前 phase；
- 无 transition cost，退化为 Pareto-only instantaneous；
- 无 minimum residency window；
- 禁用 `PARTITIONABLE`，将相关阶段退化为完整设备配置；
- 无CPU核心隔离；
- 无 SM 分配，退化为默认 CUDA 不受控共享；
- 固定 SM 分配，不根据工作流状态或画像调整；
- 无驻留迟滞；
- 无KV保存；
- 固定设备放置。

敏感性：

- KV / context 长度；
- TTS chunk 长度；
- Diffusion 时长；
- 图像队列深度；
- 预测误差；
- predictor 的画像覆盖率、MAPE、绝对误差 p95 与 decision regret；
- 显存安全余量。
- SM 分区粒度与 TTS 最小有效 SM 数；
- GPU utilization 或带宽压力预测误差。

泛化不能只由 phase 接口的抽象命名证明。主链路通过后，正式 evaluation 至少覆盖两个变化轴，
并尽量包含一个替代模型或后端实例：LLM 规模/context、TTS backend/chunk 数、GPU burst 类型或
Diffusion 参数、queue depth/burst arrival pattern、co-runner/冷热状态。所有变化必须复用相同的
phase/profile/PlacementPlan 接口，不能为新模型增加专用调度分支。
